# ClubOn




> 프리미엄 온라인 화상 소셜 클럽. 그룹 테이블 기반 만남, AI 라운지 매니저 매칭, 마스크 착용 대화, 상호 동의 얼굴 공개.

성인 전용 회원제 서비스이며, **1:1 데이팅 앱이나 랜덤 화상 채팅 서비스가 아닙니다.**
모든 대화는 최소 4명 이상의 그룹으로 시작합니다.

---

### 환경 변수

| 변수 | 필수 | 설명 |
|---|:-:|---|

| `GOOGLE_CLIENT_SECRET` | Google 로그인 시 | **서버 전용.** OAuth 클라이언트 보안 비밀번호 |
| `NEXT_PUBLIC_SUPABASE_URL` | – | Supabase 프로젝트 URL |

| `CREEM_WEBHOOK_SECRET` | 결제 사용 시 | **서버 전용.** 웹훅 서명 검증용. 없으면 웹훅을 503으로 거부합니다 |
| `CREEM_MODE` | – | `test`(기본) 또는 `live` |
| `CREEM_*_PRODUCT_ID` | 결제 사용 시 | 상품별 Creem 상품 ID. 채워진 상품만 판매됩니다 |
| `DAILY_API_KEY` | 화상 사용 시 | **서버 전용.** Daily 방 생성·미팅 토큰 발급용. 없으면 화상 없이 채팅만 동작합니다 |

> 이 상태에서도 전체 화면 플로우를 확인할 수 있으며, 데이터는 프로세스 재시작 시 초기화됩니다.

### Google 로그인 설정

1. [Google Cloud Console](https://console.cloud.google.com) → **API 및 서비스 → OAuth 동의 화면**을
   구성합니다(외부 / 앱 이름 / 지원 이메일).
2. **사용자 인증 정보 → OAuth 클라이언트 ID 만들기 → 웹 애플리케이션**을 선택하고,
   **승인된 리디렉션 URI**에 아래를 그대로 등록합니다. 문자 하나라도 다르면 Google이 거부합니다.

   ```
   http://localhost:3000/api/auth/google/callback
   https://<배포도메인>/api/auth/google/callback
   ```

3. 발급된 클라이언트 ID·보안 비밀번호를 `GOOGLE_CLIENT_ID`·`GOOGLE_CLIENT_SECRET`에 넣습니다.

인증 방식은 **Authorization Code + PKCE**이며, Google 토큰은 서버에만 머무릅니다.
로그인이 확인되면 이 앱의 기존 세션 쿠키(`clubon_session`)로 갈아타므로, 이후 코드는
Google 로그인과 이메일 로그인을 구분하지 않습니다.

#### 계정 연결 규칙

회원을 찾는 순서가 곧 신뢰 순서입니다 (`src/lib/auth/google-account.ts`).

| 순서 | 기준 | 동작 |
|---|---|---|
| 1 | `users.google_sub` | 이미 연결된 계정. **이후 모든 로그인은 이 경로** |
| 2 | 확인된 이메일 | 첫 Google 로그인. 기존 계정에 `google_sub`를 붙입니다 |
| 3 | 없음 | 비밀번호 없는 계정을 만들고 온보딩(성인확인)부터 시작 |

`google_sub`은 Google 계정의 **불변 식별자**(id_token의 `sub`)입니다. 이메일은 바뀔 수도,
해지 후 다른 사람에게 재배정될 수도 있으므로 한 번 연결한 뒤로는 주소가 아니라 이 값으로
계정을 찾습니다. 덕분에

- 회원이 Google 주소를 바꿔도 **같은 계정**으로 들어오고, 앱의 이메일도 따라 갱신됩니다
  (단, 새 주소를 이미 다른 회원이 쓰고 있으면 갱신을 보류하고 로그인만 통과시킵니다).
- 예전 주소가 **다른 사람에게 재배정**되어도 그 사람은 `sub`가 달라 남의 계정에 닿지 못하고
  별도 계정으로 가입됩니다.
- 한 Google 계정이 여러 회원 계정에 붙지 않도록 DB에 부분 유니크 인덱스를 겁니다.

> **남은 틈**: 2번(최초 이메일 연결)은 여전히 이메일을 신뢰합니다. 누군가 남의 Gmail 주소로
> **먼저 이메일 가입**을 해두면, 주소의 실제 주인이 첫 Google 로그인을 할 때 그 계정에
> 연결됩니다. 이메일 가입에 인증 메일 절차가 없어 생기는 문제이므로, 완전히 닫으려면
> 가입 시 이메일 인증을 추가해야 합니다.

## 미리보기 단계: 로그인 없이 사용

현재 단계에서는 **로그인 없이 모든 기능을 그대로 쓸 수 있습니다.**
세션 쿠키가 없으면 데모 회원(하나)으로 자동 입장하며, 헤더의 **회원 전환기**로
다른 데모 회원(관리자·모더레이터 포함)으로 바꿔 볼 수 있습니다.
관리자 콘솔처럼 역할이 필요한 화면도 전환기에서 `관리자`를 고르면 확인됩니다.

로그인·회원가입(`/login`, `/signup`)과 온보딩(성인확인 → 동의 → 프로필)도
구현되어 있으며, 원할 때만 사용하는 선택 경로입니다. 로그인하면 그 계정으로
동작하고, 로그아웃하면 다시 데모 회원으로 돌아갑니다.

> 회원 전환기와 데모 계정 안내는 `DATABASE_URL`이 없는 인메모리 모드에서만
> 노출됩니다. 실제 DB를 연결하면 로그인한 회원만 통과합니다.

### 혼자서 전체 플로우 보기

합석 룸은 **총 4명 이상**이어야 열립니다(1:1 매칭 금지). 혼자 둘러볼 때는
라운지 화면의 **`데모 동반자 합류시키기`** 버튼으로 내 라운지 인원을 채우면
매칭 → 마스크 대화방까지 이어집니다. 상대 라운지가 데모 라운지인 경우
라운지 매니저가 상대 측 수락을 대신 처리합니다.

## 다국어

회원 화면은 **11개 언어**의 뼈대를 갖추고 있으며(`src/lib/i18n/locales.ts`),
문구는 한국어와 영어가 채워져 있습니다. 나머지 언어는 빈 사전이라 자동으로
영어로 떨어집니다 — 사전 파일만 채우면 코드를 건드리지 않고 켜집니다.

- **언어를 고르는 순서**는 직접 고른 값(쿠키) → 브라우저 `Accept-Language` →
  한국어입니다. 직접 고른 값이 언제나 이깁니다.
- **기준 사전은 한국어**(`dictionaries/ko.ts`)입니다. 키 구조의 진실이 여기
  있으므로 새 문구는 반드시 여기부터 넣습니다. 다른 언어는 부분만 채워도 되며,
  빠진 키는 타입 오류가 아니라 폴백(영어 → 한국어)으로 다뤄집니다.
- **문구는 컴포넌트에 적지 않습니다.** 서버 컴포넌트는 `getT()`, 클라이언트
  컴포넌트는 `useT()`를 씁니다.

### 값과 표기를 가르는 규칙

관심사·연령대·신고 사유처럼 **DB에 저장되는 값이 한국어 문자열**인 것들이
있습니다. 이 값들은 매칭과 기록의 키라서 바꾸지 않고, 화면에 보이는 글자만
사전에서 찾습니다(`interestLabel`, `reportCategoryLabel` 등). 상품명·매니저
소개·동의 항목도 같은 이유로 카탈로그가 아니라 사전에 있습니다.

### 저장되는 문장

방 안의 시스템 안내, 매칭 사유처럼 **서버가 만들어 저장했다가 나중에 여러
사람이 함께 보는** 문장은 문장이 아니라 **키와 사실**로 저장합니다. 한 방에
서로 다른 언어를 쓰는 사람이 함께 있을 수 있어, 저장 시점에 한 언어로 굳히면
나머지는 읽지 못하는 안내를 보게 되기 때문입니다. 문장은 뷰를 조립할 때
보는 사람의 언어로 만듭니다(`buildRoomView`, `describeReason`).

### 아직 한국어만 있는 곳

- **이용약관·개인정보 처리방침** — 회원이 법적으로 동의하는 문서라 기계 번역으로
  대체하지 않습니다. 한국어가 아닌 언어에서는 "한국어로만 제공된다"는 안내를
  먼저 띄웁니다. 번역본은 법률 검토를 거친 뒤 올립니다.
- **동의 항목 문구**는 영어까지 옮겨 두었지만, 실제 서비스 전에 법률 검토가
  필요합니다.
- **관리자 화면**은 운영자용이라 번역하지 않았습니다.

## 30분 라운지 이용권 · 결제

구독이 아니라 **쓰는 만큼 구매하는 이용권** 방식입니다. 이용권 1회 = 30분 라운지 한 자리.

### 상품

가격·혜택의 단일 출처는 `src/lib/payments/catalog.ts`입니다. 화면과 서버가 모두 이 표만
참조하므로 컴포넌트에 값을 다시 적지 마세요.

| 코드 | 상품 | 가격(USD) | 이용권 | 1회당 |
|---|---|---:|---:|---:|
| `one_time` | ONE TIME | $4.99 | 1회 | $4.99 |
| `light` | LIGHT | $23.99 | 5회 | $4.80 |
| `gold` | GOLD | $29.99 | 10회 | $3.00 |
| `black_vip` | BLACK VIP | $79.99 | 20회 + VIP 혜택 | $4.00 |

금액은 **USD 센트 정수**로 다룹니다(반올림 오차 방지).

### Creem 설정

1. Creem 대시보드에서 위 4개 상품을 **일회성(one-time) 결제**로 만듭니다.
2. 각 상품 ID를 `CREEM_ONE_TIME_PRODUCT_ID` 등 환경 변수에 넣습니다.
   비어 있는 상품은 화면에 "결제 준비 중"으로 표시되고 결제가 시작되지 않습니다.
3. 웹훅 엔드포인트를 등록합니다.

   ```
   https://<배포도메인>/api/payments/creem/webhook
   ```

4. 웹훅 시크릿을 `CREEM_WEBHOOK_SECRET`에 넣습니다.

### 지급과 차감이 일어나는 지점

- **지급은 웹훅에서만** 일어납니다. 브라우저가 성공 URL로 돌아온 것만으로는 아무것도
  지급하지 않습니다(주소창은 누구나 입력할 수 있습니다). 성공 화면은 "확인 중" 안내만 합니다.
- **멱등성**은 `payments.payment_id`(Creem 주문 ID) 기본키가 보장합니다. 웹훅이 재시도로
  여러 번 도착하거나 동시에 도착해도 지급은 1회뿐입니다.
- **차감은 영상 라운지 입장 시점**(`/api/rooms/[sessionId]/video`)에 **방 하나당 1회**.
  매칭을 기다리는 동안에는 차감되지 않고, 참가자 수와도 무관하며, 매칭을 요청해 방을 연
  라운지의 방장이 부담합니다. `lounge_usages.session_id` 기본키로 멱등이라 새로고침·재접속은
  물론 여러 명이 **동시에** 입장해도 중복 차감되지 않습니다. 동시 입장 시에는 부담자의
  지갑 행을 `for update`로 먼저 잠근 뒤 기존 기록을 읽으므로, 뒤늦은 트랜잭션은 앞선
  트랜잭션이 커밋한 행을 보고 조용히 무료 입장으로 처리됩니다.
- **30분 만료**는 서버가 `lounge_usages.expires_at`에 저장합니다. 클라이언트 타이머는 이 값과
  현재 시각의 차이를 다시 계산할 뿐이라, 새로고침하거나 다른 기기로 접속해도 시간이
  되감기지 않습니다. 만료 후에는 화상 토큰이 재발급되지 않습니다.
- **환불**은 남은 이용권만 회수합니다. 이미 사용한 분은 되돌리지 않으며 잔액이 음수가 되지
  않습니다.

### 시간 연장

이용권을 쓰지 않고 **돈을 받아 그 방의 만료 시각을 뒤로 미는** 상품입니다. 영상방 하나에
이용권 1회이므로 "이 방의 시간"은 함께 쓰는 자원이고, 그래서 연장은 늘 **방 전체**에
적용됩니다. 돈은 버튼을 누른 사람에게서만 빠집니다.

| 코드 | 상품 | 가격(USD) | 연장 | 살 수 있는 사람 |
|---|---|---:|---:|---|
| `extend_10` | 10분 연장 | $1.99 | 10분 | 방을 연 회원(부담자) |
| `extend_30` | 30분 연장 | $3.99 | 30분 | 방을 연 회원(부담자) |
| `gift_extend_30` | 30분 연장 선물 | $3.99 | 30분 | 그 방의 다른 참가자 |

- **판매 위치**는 멤버십 화면이 아니라 **영상 라운지 안**입니다. 남은 시간이 5분 아래로
  내려갔을 때와 시간이 끝난 뒤에만 버튼이 나옵니다 — 30분 내내 결제를 권하지 않습니다.
- **누가 무엇을 사는지**는 서버가 정합니다(`RoomView.extensions`). 부담자에게는 연장이,
  나머지 참가자에게는 같은 일을 대신 해 주는 선물이 보입니다. 체크아웃 라우트에서
  ① 요청자가 그 방의 활성 참가자인지 ② 늘릴 이용 기록이 있는지 ③ 자기 자리에 맞는
  상품인지를 다시 확인합니다.
- **어느 방을 늘릴지**는 성공 URL의 쿼리스트링이 아니라 Creem이 되돌려주는 metadata로만
  판단합니다. 지급과 마찬가지로 브라우저가 돌아온 사실은 근거가 되지 않습니다.
- **적용은 결제 기록과 같은 트랜잭션**입니다. 중복 웹훅은 `payment_id` 기본키에서 막히므로
  시간도 두 번 늘어나지 않고, "기록은 남았는데 시간은 그대로"인 상태도 생기지 않습니다.
- **기준 시각은 `greatest(expires_at, now())`**입니다. 결제 승인이 늦게 도착해 그사이
  만료된 방도 산 시간을 온전히 받으며 다시 `active`가 됩니다. 다만 **호스트가 직접 끝낸
  방(`ended`)은 되살리지 않습니다** — 아무도 없는 자리에 시간만 붙기 때문입니다. 이때는
  결제 기록만 남기고 서버 로그에 "환불 필요"로 남깁니다(웹훅을 실패로 돌리면 Creem이
  영원히 재시도합니다). 판매한 분 수와 실제로 늘어난 분 수는 관리자 화면에서 비교합니다.
- **제공량**은 `lounge_usages.extended_minutes`에 분 단위로 누적됩니다. 이용권 차감과는
  별개의 과금이라 판매 통계도 따로 셉니다.
- **환불**은 이용권을 0회 회수합니다(연장은 이용권을 준 적이 없습니다). 이미 흘러간 시간은
  되돌리지 않습니다.

### 아직 팔지 않는 추가 과금(재매칭·조건 지정)

`ADDONS`에 가격은 정의되어 있으나 이행 로직이 없어 **체크아웃 자체를 시작하지 않습니다.**
받아 놓고 아무것도 주지 못하는 상황을 만들지 않기 위해서입니다. 판매 가능 여부의 기준은
`extendMinutes`가 정해져 있는지 하나뿐입니다(`getExtensionAddon`).
